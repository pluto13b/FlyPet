# 自动暂停诊断与可恢复调度

2026-09-20。用户反馈经常自动停止。正式日志确认出现“全脑计算持续落后，模拟已暂停”；最近成功摘要中 pendingMs=899，随后自动保存每 15 秒重复抛出相同故障。重复日志不等于每 15 秒发生一次新过载，摘要中的 paused=false 也可能只是故障前的旧保存。

根因机制：积压超过 1000 ms 被 `WholeBrainBridge.fail` 标记为永久故障，清掉在途请求，后续 step 和 checkpoint 均无法继续；点击继续也会再次被 `pet.step` 暂停。重启还会恢复旧 pendingMs，可能很快再次撞线。

实时全脑及 flyvis 目前使用 CPU，GPU 用于渲染和此前训练。检查时全机 CPU 约 45%，剩余内存 7.7/31.7 GB，GPU 约 37%、显存 4068/8188 MiB。这是故障暂停后的瞬时样本，不代表过载发生时的峰值；没有证据证明内存或显存不足。

本轮修正：积压超过 250 ms 时暂缓身体／年龄推进，停止新增感觉采集，继续处理已有脑计算；降到 100 ms 内自动恢复。积压本身不再进入永久故障，保存仍可用。旧排队等待计数作为运行期状态不跨进程恢复，神经元动态、年龄、个体和学习状态不清零。进程退出、请求超时等真实错误仍停止模拟。

界面明确显示“追赶计算，暂缓运动”，与用户主动暂停区分。只做调度修复，不训练或修改神经模型。

## 实施与验证

已将可恢复积压与进程故障分开。真实 worker 测试人为制造 1100 ms 以上的排队状态，确认年龄与身体不继续积累、故障标志保持为空、检查点保存仍成功；放开调度后队列排空并自动继续。随后终止测试脑进程，确认真正故障仍暂停。旧存档中 899 ms 等排队计数不会在重启时重新注入。

面板增加待算毫秒数与自动追赶次数。低负载时仍尽量实时运行；持续高负载时会放慢，不承诺任何负载下都实时。该策略不丢弃当前队列中的神经步骤；跨进程恢复时清理的是调度等待计数，不是已保存的神经元动态。

本次修复需要重启已经进入永久故障的旧进程。由于旧程序故障后保存也被拒绝，正式个体只能恢复到最近一次成功检查点：2026-09-20 09:03:07 UTC，ID `8a7299a1-542b-4e3c-b1e8-49546be21dcf`。不把故障后的墙钟时间补算为苍蝇经历。

验证结果：[核心测试](../output/verification/core-tests.txt) 20 项通过（真实 worker 测试包含积压恢复、保存可用和致命故障保护）；[桌面报告](../output/verification/desktop-smoke.json) 2026-09-20 09:40:00 UTC 为 `passed: true`，30.89 秒墙钟推进 30.65 秒模拟，最大待算时间 135 ms。此次常规桌面运行未触发追赶，恢复路径由前述人为积压实验验证；没有声称完成全天满负载压测。
