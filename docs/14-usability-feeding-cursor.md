# 可用性：投喂、鼠标可见性与测试图案

> 已完成的最新可用性专题。糖水为手动产品机制，自动识别美食视频仍未实现；整体状态见 [项目进度](04-progress.md)。

用户反馈三项：长期饥饿/美食视频无反应，视觉里看不见鼠标但警觉增加，测试视野外观重复。

## 原因与本轮处理

1. 当前饥饿只随时间增加，没有进食入口；官方 flyvis 是运动视觉观察模块，不识别食物、不驱动觅食。本轮补充手动糖水投喂、持续进食降低饥饿及对应字幕/状态；明确这是桌宠资源机制，不伪称已恢复神经进食回路。不把播放美食视频自动标成“识别成功”。
2. 截图没有合成系统鼠标，而鼠标几何通道独立刺激 LC4/LPLC2。使用 Win32 提取当前系统光标，在原始图像进入两条视觉链路之前合成；定位标记仅辅助显示，图像本身也真实包含光标。界面将几何感知明确标为独立通道。
3. 现有 right/left/scroll 都是周期性正弦条纹。改为右移亮块、左移暗圆和向上滚动的页面图案，提供清楚的输入来源说明，避免当作三种真实视角。

## 验收

投喂降低饥饿，暂停冻结进食进度，恢复保持个体与进食状态；真实光标形状进入图像，屏幕外光标不污染图像；三种测试图案确实不同且移动方向正确。跑桌面按钮/输入切换检查，并保留原个体存档。

## 已完成

- 新增“喂一滴糖水”，6 秒有效进食时间，饥饿以每秒 0.12 下降；GF 逃逸优先，逃逸期间暂停进食。进食状态、进度和投喂次数随同一个体保存。加入“吃。”字幕及口器动作。
- 使用 GetCursorInfo/GetIconInfo/DrawIconEx 在截取的 RGB 像素中合成真实光标，处理热点和图像边界；临时 GDI 资源在每次调用后释放。全脑输入与官方 flyvis 观察输入都使用该处理。橙圈仅为位置标注，不代替实际像素输入。
- 原三种正弦条纹改为右移亮块、左移暗圆和页面向上滚动，并将选项分为“真实输入”和“测试图案”。
- 10 项 Node 测试通过；原生光标测试确认 570 个像素受到实际光标绘制影响，屏外不污染画面；图案形状及方向检查通过。
- 桌面集成确认光标进入官方复眼、按钮投喂实际降低饥饿，并通过全脑干预、存档恢复、三维图交互和约 30 秒持续调度检查。

证据：output/verification/visual-input-tests.json、core-tests.txt、desktop-smoke.json。

美食视频自动觅食仍未实现。官方 flyvis 目前仍是独立运动视觉观察模块，手动投喂没有给它添加食物语义或学习能力。本轮没有改作者模型参数，也没有把视频播放事件当成识别食物。
