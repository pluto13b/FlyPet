## 1. 我们开始搭建什么“身体”

已有三维外观、运动动画和全脑模拟，但身体还缺少稳定的感觉—行动—结果联系。接下来补的是功能意义上的身体：知道自己在动、是否累、是否接触食物，以及行动是否带来结果。不是再画一具更精细的模型，也不首先引入整套关节、肌肉或代谢仿真。

Life Layer 是一层薄的身体状态和行为协调。优先整理现有 Hunger、Fatigue、Arousal 等变量，避免重复建立 Energy、Fatigue、Curiosity 多套相近数值。工程近似明确标注，不把这些变量说成已经测得的生理血糖、激素或真实情绪。

目标闭环：环境变化 → 实际感觉 → 结合身体需要与学习价值 → 行动 → 接触／摄入／威胁结果 → 状态和记忆改变。

## 2. 已确认的首版范围

| 目标 | 首版要做的事 | 暂时不做 |
|---|---|---|
| 稳定行为 | 减少固定左右摆动、无外因逃逸和阈值切换抖动 | 不把所有随机活动清零，不追求固定巡逻轨迹 |
| 身体状态 | 饥饿、疲劳、短时警觉；活动和摄入有实际影响 | 完整激素系统、额外能量条、昼夜睡眠模拟 |
| 一个互动闭环 | 发现线索、接近糖水、接触进食、形成关联 | 任意美食识别、完整桌面地图、复杂长期关系 |
| 可观察 | 显示真实参与决策的感觉、倾向及最近后果 | 不用心理百分比或事后生成的理由包装动作 |

苍蝇保持独立，可以犹豫、偶尔走神和失败。宠物感来自用户的操作有后果、经历留下影响，不来自每次投喂都听话或一直追随鼠标。

## 3. 控制分工

| 部分 | 应承担的职责 |
|---|---|
| 世界接口 | 桌面坐标、可接触的糖水、实际画面和鼠标事件；目标消失时使其失效 |
| 感觉／学习模型 | 对实际输入产生响应，更新并输出线索价值 |
| 身体状态 | 调节行动需求与成本，反馈活动、休息和摄入 |
| 行为协调 | 选择／维持行动，处理打断及完成条件 |
| 运动执行 | 根据速度和转向意图执行步行、起降、避边，不额外编写探索目标 |

不要求每个动作都由某个神经元阈值单独决定。可以使用混合接口，但必须说明来源：若生活层决定方向再刺激神经元，这是工程指令通过神经接口，不宣称为神经自主选择。

现有 WALK 是运动方式，EXPLORE／APPROACH 是目的，不必全部作为同一级状态。行为保持采用退出／进入差异和短暂保持，威胁、目标消失及到达仍能打断；不采用无条件“走满三秒”。具体时长属于待实测的体验参数。

## 4. 社区和论文中值得借鉴的经验

### A. FlyGym / NeuroMechFly：先有简单方向接口，再驱动身体

FlyGym 将脑级感觉与决策和低层运动分开；旧版视觉教程还展示了从视网膜画面提取目标位置、大小，再调节运动的示例。启发是先解决有限场景里的目标方向，不需要一开始训练全部关节控制。[项目](https://github.com/NeLy-EPFL/flygym/)、[旧版视觉教程](https://flygym.readthedocs.io/latest/tutorials/vision_basics.html)

对 FlyPet：先借分层方式及图像坐标读出思路，继续用现有身体动画。教程中的简化目标检测不等于生物视觉理解，更不等于我们的食物模型已经能定位；人工目标坐标也不能冒充视觉测量。

**版本注意**：当前作者 README 说明 FlyGym 2.x 在 2026 年重写 API，旧版迁移为 `flygym-gymnasium`，且并非所有旧功能都已迁入。后续若复用具体示例，应固定其对应版本，不直接混用旧论文教程和最新 API。本轮只查阅，没有安装或做性能实测；作者 GPU 加速数字不作为本机预估。[版本说明](https://github.com/NeLy-EPFL/flygym/releases)

### B. flybody：复杂身体也应有明确控制任务

作者提供 MuJoCo 果蝇身体及运动强化学习任务，适合未来确实需要物理关节、接触或飞行动力学时参考。它不是糖水互动或学习偏好的即插即用组件。[作者仓库](https://github.com/TuragaLab/flybody)

对 FlyPet：现阶段优先保留已能显示的身体，补上接触和结果事件；不因为有精细身体项目就迁移整套物理系统。

### C. fly-api：到达目标后，信号弱不一定表示应该继续找

社区导航报告把学习读出接到转向，但明确承认方向和到达规则是工程接口；作者还遇到目标附近学到的抑制使左右信号都很弱的情况，需要减速／到达处理。[导航报告](https://github.com/dtch1997/fly-api/blob/main/experiments/navigation/report.md)

对 FlyPet：需要区分“没看见目标”“已经到达”“接触后正在吃”。不能让趋近分数独自承担目标存在、目标方向和进食结束三种职责。该项目低 star，仅作具体经验参考，不能把其示例数值当作本机验证。

### D. 味觉实验：接触、停下、摄入不是同一件事

2016 年研究描述了足部甜味感受神经元在进食启动与运动停止中的功能差异。[论文](https://www.nature.com/articles/ncomms10678)、[可检索全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC4762887/)

可借鉴的产品顺序是：接触糖水 → 抑制继续行走 → 摄入 → 饥饿下降并提供学习信号。这里只借鉴行为组织，不声称已复现对应足部／腹神经索回路。单纯“点击投喂→reward+1”无法替代摄入后果；正常喂养与实验性直接奖励按钮应区分。

### E. 糖后局部搜索：一种比固定巡逻更有生活感的灵感

2023 年的实验方法论文介绍糖摄入后局部搜索的追踪；文中描述了饥饿果蝇摄糖后的迂回及环状路径。[论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC7615537/)、[DOI](https://doi.org/10.3791/65955)

对 FlyPet 的后续灵感：获得少量奖励后，在附近短暂探索，再逐渐离开。它可以让用户看到一次喂养的余波。**这是后续候选，不是首版必做，也不是给轨迹直接画圆。** 若采用工程近似，应按真实发生的摄入事件触发并标明简化，不包装成原全脑自发复现。

2023 年嗅觉运动研究同样提示，搜索不仅是“直奔一个坐标”，速度与曲率变化也有作用；只作为行为多样性的依据，不在本轮新增嗅觉模型。[论文](https://www.nature.com/articles/s41467-023-42613-8)

## 5. 哪些想法先保留、但不立即实现

- **安全区／窝**：经常停留不等于安全；可能只是卡边。先不把固定窝说成果蝇天然习性。
- **兴趣区**：画面变化、历史奖励、低威胁是不同证据；不要把运动多或停留久直接变成高奖励，否则会一直追逐视频或滚动页面。
- **鼠标关系**：先做短时警觉和恢复；长期“亲密度”或鼠标威胁学习暂缓。鼠标模式不等于用户身份。
- **好奇心**：可先作为低强度探索倾向，不再做一个没有独立后果的百分比状态。
- **奖励归因**：进食时看到的鼠标／糖水标记可能覆盖原先线索。应优先核对已有学习模型的时间机制，不把最后一帧任意当作奖励对象。

## 6. 对工程投入的判断

整理状态、减少抖动和改善逃逸读出属于现有代码的局部修改。最大的工作在“把画面评分变成可持续接近的实际位置”，以及“接近后真正发生接触和摄入”。目前独立分类实验的 AUC 0.646 不能代替这个过程。

不为了保留全脑控制的名义增加一条无效接口，也不让生活层决定所有动作后仅展示神经活动。每接通一条控制关系，都应能直观看到相应输入变化带来的行为变化。

最小验收场景：放下一滴糖水，它有机会发现并接近，接触后停下进食，身体状态发生变化；之后相同线索更值得靠近。换位置或撤掉目标时行为相应改变。允许偶尔失败，不需要十种行为或论文式实验才能交付。
