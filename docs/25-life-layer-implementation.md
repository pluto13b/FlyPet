## 1. 实现顺序

先把身体与环境接通，再决定是否需要微调。训练只解决已有输入、结果和动作接口上的具体问题，不用延长训练掩盖接口缺失。

| 小迭代 | 实际交付 | 是否训练 |
|---|---|---|
| A：行为稳定 | 减少周期性左右摆动、无威胁乱飞及频繁动作切换 | 不需要 |
| B：糖水有位置 | 用户放下一滴糖水；接触后才能进食、降低饥饿 | 不需要 |
| C：看到后能接近 | 局部画面真实取样、已有模型评分、转向与目标失效处理 | 先用现成权重；必要时短时适配 |
| D：经历改变偏好 | 接触摄入产生奖励，更新小型学习回路并保存 | 局部在线学习；不训练整个全脑 |

每一步都以可见效果验收，先不加安全区、睡眠、亲密度和长期鼠标恐惧。开发、调试、训练墙钟分别报告；不把训练只需几秒说成全部集成几秒完成。

## 2. 对现有代码的最小修改

### 行为协调：先整理 `pet.mjs`，不另建大型框架

- 复用当前饥饿、疲劳和警觉状态。活动消耗、休息恢复、摄入降低饥饿，作用方向清楚即可。
- 去掉每隔固定时间轮换左右方向的正弦驱动。无目标时保留低强度、有持续性的探索；探索方向不伪装成视觉目标。
- 神经读出参与速度／转向，但单次 GF 放电不再无条件触发长飞行。先要求短时威胁证据与神经信号共同支持，并保留手动刺激作为明确实验干预。
- 行走／梳理／休息使用短暂保持及进入／退出差异，避免阈值附近抖动。实际威胁、目标消失和到达可以打断，不强制走满固定三秒。
- `motion.mjs` 继续负责平滑速度、姿态和边缘处理，不承担找食物决策。

这是工程行为协调，不声称重建了缺失的腹神经索。主要原因面板同时说明“模型读出”“身体状态”及“工程约束”，不把融合后的决定一概归功于全脑。

### 糖水：一个可接触的世界对象

第一版只允许一滴糖水，使用放置模式在桌面选择位置，Esc 取消。正常时不拦截其他桌面点击。糖水有位置、接触范围和剩余量；无需物理引擎。

身体世界接口可以知道糖水位置，用于绘制与接触判断；视觉评分不能直接拿到这个坐标或“这里有食物”的标签。到达但没有摄入，不发摄入奖励；飞行越过糖水不算自动吃到。

画面中的糖水要实际进入感觉输入。现有苍蝇／观察室窗口开启内容保护，不能直接复用它们承载糖水后假设截图一定能看见。实现时选择独立可采集的食物层，或在世界输入图像里绘制糖水像素；必须核对最终神经输入，而不只核对人眼所见。

### 视觉：先小范围取样，不实时扫描整屏

复用 `OfficialVision` 独立进程与固定 flyvis。先比较身体前方左／中／右三个局部图像块，使用与实验一致的预处理、Tm3 空间特征及已保存投影／学习权重。每个候选的相对方向来自图像取样位置，价值来自模型；没有用食物标签定位。

三个局部块是工程感觉适配，不是测得的真实复眼视野。先以约 2 Hz 的候选更新作为待测起点，身体渲染保持原节奏；这是目标而非已有性能保证。结果过期就放弃，不能为了等模型阻塞 Electron 主进程。

取得稳定偏好后转向对应方向，并随身体移动重新观察；不持续追逐一次截图里的旧坐标。目标移动、消失或连续几次没有证据时，回到探索。没有明显评分差异时允许不选择，不能强制把三个分数最高者都当食物。

首版不做网页 DOM 解析、全屏物体检测或任意 B 站窗口识别。视觉候选能否在当前局部取景下区分，是集成中最先需要实测的点。

## 3. 学习和微调具体放在哪里

### 优先：只更新已接入的学习回路

保持官方 flyvis 权重固定；先从已保存的类别记忆起步，保留原始检查点作为对照。当前类别结果仅 AUC 0.646，不能假设换成局部桌面图就一定有效。

采用“摄入发生→学习回路接收奖励”的事件。保留近期候选线索及时间，用于检查奖励与所见线索的配对；不要把点击投喂按钮等同于摄入，更不要每个渲染帧都追加奖励。时间窗口和更新节奏以所用作者模型的协议为参照，不能直接在 2 ms 全脑步长下重复更新。

先让一种明确的图案与糖水形成稳定关联，观察体验后再评价多种食物图片。糖水标记本身可能成为主要线索，这是应显示的实际结果；不能把学会标记说成学会原视频内容。

### 需要时：小批量适配真实取景

若原实验图片有效、实际局部画面无效，先收集少量同一取景接口产生的图片（位置、缩放、遮挡变化），短时训练 KC→MBON 学习连接。训练／验证／测试仍简单分开，少量参数选择即可，不再展开大量对照。

不默认微调官方视觉网络，也不扩大全脑。如果这一步仍无效，先报告是特征不足、定位失败还是决策接口问题；不要自动切换大训练来追分。

仅当已有证据表明视觉特征不足且确有可复用小范围训练方案时，才另行提出视觉微调的明确任务、耗时和验证标准。这样可以保留原有运动视觉能力，避免用少量封面把它改坏。

## 4. 默认训练预算与停止规则

为落实“不训练一整天”，后续实施采用以下默认项目约束：

- **单次离线训练最多 10 分钟墙钟；同一轮尝试累计最多 30 分钟。** 这是本项目选择的预算，不是已有训练耗时，也不包含人工开发时间。
- 计时从实验运行开始，不只统计 GPU 内核；数据准备、特征提取、训练分别显示耗时。长准备任务不能藏在“训练很快”的表述里。
- 至多试少量预先指定配置；到时间先保存已完成检查点和结果，停止，不自动后台续跑或隔夜重试。
- 若要超过上述预算，先说明原因与预计收益，不默认加时。暂不购买云算力或安装新大型训练环境。
- 日常在线学习是少量事件驱动更新，不是常驻高负载训练；需保证不会拖慢桌面交互。

优先使用现有 `D:\Desktop\deeplearn\conda_envs\tudui` 的 PyTorch CUDA 与 RTX 4060，缓存和新文件仍限定 `D:\Desktop\FlyPet`。小更新若 CPU 更快则用 CPU，不为了使用 GPU 强行增加批量或改模型。

已有证据：上次 130 张图固定视觉特征提取约 9.11 秒，GPU 四组记忆训练与评分约 3.32 秒；32 个小型配对模型的 GPU 更新核心约 0.106 秒。这些说明小回路实验成本低，**不保证实时感知或未来视觉微调也有同样耗时**。

## 5. 保存与可观察性

正式个体的原 ID、全脑动态和经历继续保留。真正接入学习时，将学习权重、必要短时状态、模型版本及随机状态与个体一起保存；不能只保存一个“食物偏好分数”。具体沿用现有检查点流程扩展，不另建存档平台。

面板优先显示：当前动作、主要原因、目标方向／证据是否新鲜、饥饿／疲劳／警觉、最近一次接触和奖励。避免把任意单位读出叫成食物概率或心理百分比。

首个可见验收：放置糖水后它有机会发现、转向、接近、停下摄入；移动或撤掉目标后行为变化；进食后的同一线索可影响下一次选择；重启后仍是同一个体并保留已验证的记忆。允许失败和犹豫，但不能仍然无论看什么都固定绕圈。
