# 桌面窗口坐标报错修复

> 已完成的故障记录。负零坐标修复已保留在当前代码；本文件的排查过程是历史过程。当前验证见 [项目进度](04-progress.md)。

用户报告主进程 app.cjs:130 的 setPosition 第二个参数转换失败，定时器每 20 ms 调用该接口，故未处理异常会反复弹框。

先用独立隐藏 Electron 窗口检查整数、负零和非有限数的参数转换行为，再修复坐标生成处，增加对应回归测试。保留正式个体存档，不重置个体；验证后重启正式进程。

最初排查假设（已在下文实测确认）：Math.round 在坐标略小于零时生成 JavaScript 的 -0，Electron 原生整数参数转换可能拒绝它。最终结论以实测为准。

## 实测结论与修复
- 隐藏 Electron 窗口复现了 setPosition(100, -0) 的相同异常；普通 0、负整数均正常。
- 在所有传入窗口/显示器原生 API 的坐标上使用 Math.round(value) + 0，规范化负零，不改变正常负坐标。
- 6 项核心测试通过；原生窗口验证中修复后的五组边界坐标全部通过；桌面集成 smoke 通过。
- 已关闭旧进程的错误弹框，确认正式个体完成存档后重启修复版本，未重置存档。
- 证据：output/verification/position-probe.json、core-tests.txt、desktop-smoke.json。
